### Задание 1. Кеширование

Приведите примеры проблем, которые может решить кеширование.

Приведите ответ в свободной форме.

1. Производительность и Скорость Отклика

*Проблема*: Медленные операции чтения из основного источника данных (например, реляционная база данных PostgreSQL, MySQL).

*Решение*:
- снижение задержки (Latency): данные в оперативной памяти (RAM) доступны на порядки быстрее, чем с диска (даже SSD). Кэш возвращает данные за микросекунды, а не миллисекунды;
- увеличение пропускной способности (Throughput): кэш может обрабатывать гораздо больше операций в секунду, чем основная БД, разгружая её и позволяя всему приложению обслуживать больше пользователей.

2. Снижение Нагрузки на Основной Источник Данных

*Проблема*: высокая нагрузка на основную базу данных (БД) от частых и повторяющихся запросов на чтение. Это может привести к деградации производительности всего приложения, так как БД становится "бутылочным горлышком".

*Решение*: кэш выступает в роли буфера для запросов на чтение. Большинство "горячих" данных обслуживаются из кэша, а основная БД получает лишь небольшую долю запросов (в основном на запись и чтение "холодных" данных). Это позволяет основной БД работать стабильно и эффективно.

3. Масштабируемость

*Проблема*: сложность и дороговизна вертикального масштабирования (увеличения мощности одной машины с БД) имеют физические пределы.

*Решение*: кэширующий слой легко масштабируется горизонтально (добавлением новых серверов, как в кластере Redis или пуле Memcached). Это позволяет наращивать производительность системы чтения практически линейно, не трогая основную БД.

4. Повышение доступности и устойчивости к сбоям

*Проблема*: при резком всплеске трафика (например, DDoS-атака или эффект "всплеска" после рекламной кампании) основная БД может не выдержать нагрузки и "лечь".

*Решение*: кэш поглощает основной удар, защищая основную БД. Даже если кэш заполнится или часть данных устареет, система сможет какое-то время работать, постепенно подтягивая данные из БД, вместо полного отказа.

5. Экономическая эффективность

*Проблема*: обеспечение высокой производительности только за счет масштабирования мощных серверов баз данных (например, с большим объемом RAM и быстрыми SSD) очень дорого.

*Решение*: использование кластера кэширующих серверов (которые используют дешевую RAM) для обработки основной нагрузки чтения позволяет использовать менее мощные и, следовательно, более дешевые серверы для основной БД.
